# 时空镜：手机交互原型

更新：2026-10-29。当前 HTML 在同学的 v5 原型上继续迭代，采用已讨论的 A+B 组合：全屏镜头入口 + 横向年龄扉页。取景铺满当前视口，快门居中；相册与翻转镜头使用图标，模式、轮廓开关、检测状态和清除数据收进右上角“选项”。正常状态不堆叠技术小字，错误、倒计时与多人选择按需出现。旧版内容可从 Git 历史查看，同学原有的 Word 使用说明保留原样；当前行为以本文为准。

## 启动与手机演示

先看 [2026-10-29 演示录屏（MP4）](屏幕录制%202026-10-29%20125222.mp4)。保留录制原文件；GitHub 若没有显示播放器，可下载后播放。录屏展示此前版本交互，早于本轮自动拍照、占位年龄与默认轮播改动；不代表真实估龄或 GAN 已接入。

环境：Python 3 和较新的 Chrome / Edge。仓库下载或 Git 克隆方式见 [根目录快速启动](../README.md#快速启动)。

手机窄屏使用全屏取景；电脑宽窗口使用居中的手机比例预览，宽度随窗口高度缩放，最多430像素。后续页面和选项面板也保持在同一个预览范围内。

在项目根目录运行：

```powershell
python 原型/serve.py
```

电脑打开 http://localhost:65512/ 。页面和约 23 MB 的检测资源均从本地目录加载，无须 npm 安装；第一次检测需初始化 WASM 和模型。直接双击 HTML 也可以打开界面，但会尝试在线运行库，离线演示请使用配套服务器。

Windows 若使用 Python 启动器，可改用 `py -3 原型/serve.py`。保持终端运行，按 `Ctrl+C` 停止；端口被占用时可加 `--port 65513` 并访问对应地址。

同一局域网的手机，可运行 `python 原型/serve.py --bind 0.0.0.0`，通过电脑的局域网 IP 和端口访问。这个 HTTP 地址可用于上传照片演示；手机浏览器调用摄像头需要可信 HTTPS。手机中的 localhost 指手机本身，不能用它连接电脑。需要实时摄像头演示时，应将整个 `原型` 目录部署到 HTTPS 静态站点，或配置受手机信任的本地 HTTPS；模型文件路径须一起保留。

## 一次完整体验

默认流程为：开启镜头 → 所有人姿态与大小合格并保持静止 → 自动拍照 → 自动使用演示占位年龄 → 制作年龄序列 → 自动翻阅。相册照片中单脸直接继续，多脸需点选主角后确认。真实估龄模型尚未接入，目前统一使用 **30 岁演示占位**，不是估龄结果；不再要求每次填写。年龄修正与目标自定义保留在选项中。FR06 的真实自动估龄仍未完成。

1. 点底部中央快门开启镜头，或点左下相册图标选择照片。自动拍照默认开启，手动快门仍可随时使用；右上“选项”可以关闭自动拍照。支持 JPG / PNG / WEBP，最多 15 MB，短边至少 256 像素；上传大图按最长边 1800 像素缩小。
2. 实时取景默认选择较大、较居中的人脸作为年龄序列主角，多人时可点轮廓或编号切换。拍摄条件检查画面内全部检测到的人脸，生成则处理选中的一个主角。最多检测 4 脸；未被检测到的人不参与条件判断。上传照片单脸自动继续，多脸点选后确认，检测失败可拖动画框。
3. 自动拍摄要求每张脸均有可用姿态信息、大小合格、完整处于画面内，亮度与清晰度检查通过。以持续稳定区间的初始位置、尺寸和姿态为基准，稳定约 1.8 秒后倒计时 3 秒。移动、转头、尺寸变化、出现新脸、漏检、检测失败、切换目标或切换到后台会重新计时；打开选项暂停自动拍摄。阈值为原型启发式，仍需实机标定，不包含完整遮挡检测。
4. 面部关键点按双眼连线裁剪对齐到 256×256，保留逆变换参数。当前默认使用 30 岁占位，自动生成 15、40、55、70 岁四个目标，加上“此刻”原照共五页。界面、总览和导出均标明年龄来源。可在选项中修正年龄，或设置 1–8 个目标（5–90 岁）、年龄差与快捷预设。
5. 全部目标成功后自动按年龄从小到大循环翻阅，每页约 2.6 秒。结果页右上有“暂停翻阅 / 自动翻阅”；触摸扉页、点击箭头或圆点会停止自动播放。点按目标照片打开分割线对比，可切换人脸局部与回贴原图。离开结果页或切到后台会停止轮播。
6. 右上选项的“年龄总览”提供按年龄排序的拼图及 PNG 导出。“保存这一页”优先尝试系统文件分享，不支持时下载 PNG。文件带年龄来源与演示属性标注；系统分享能力取决于手机浏览器。
7. 处理状态显示逐目标排队、处理、完成、失败及实际耗时；单个失败不阻塞其他目标，可单项重试。生成接口默认超时 60 秒；估龄适配器有 4 秒等待上限，失败、超时或无效返回时使用明确标记的演示占位，迟到估龄不覆盖结果。清除操作会停止镜头和轮播，失效待处理任务，清理原图、结果与画布；已导出文件保留。

## 返回与再次拍摄

- 结果页左上角返回主页，结束并清除本次记录；底部“再拍一张”开始新记录。上一张来自摄像头时会重新请求镜头，来自相册时回到取景页，可再次上传。
- 对比页返回其来源（年龄扉页或总览），保留照片、结果及原来的页码。总览与已完成的处理状态返回结果页。
- 年龄设置从结果页进入后，直接返回会撤销未应用的年龄与目标修改，保留原结果；点击“查看年龄变化”才按新设置重新制作。
- 处理期间返回会停止后续任务；有已完成结果时可查看这些结果，没有时返回年龄设置。迟到的生成结果不会写回。
- 选项里的“清除本次数据”仍有确认框；普通的逐级返回不再误触发清空确认。

## 手机与镜子模式

手机体验与自动镜子均默认启用自动拍照，也可使用手动快门。手机拍摄后关闭摄像头，查看结果期间不会因离开镜头而清空。镜子模式保留视频检测，选中的人脸消失约 5 秒后清空，即使画面内仍有其他人，也不自动更换本次结果的主角。

两种模式均自动使用已接入适配器的有效估龄或演示占位值继续，无须强制填写年龄。当前镜子模式属于网页流程验证，不代表 RK3288 Android 应用已完成。

## 轮廓、分割与模型边界

- Face Landmarker 自带检测能力，主流程只运行这一套模型，每秒至多检测 5 次，CPU 推理；不额外叠加一次 BlazeFace。轮廓使用 36 个面部椭圆关键点，选中区域可半透明填色。
- **这实现的是逐人脸几何区域掩膜，尚未实现用户所提完整的实例分割。** 不包含头发、耳朵或身体的像素级语义，也不是生物身份识别。目标使用短时运动预测与全局匹配维持编号，显示标签、点选和拍摄沿用同一 ID，不再跟随模型返回顺序变化。短暂漏检保留约 1.2 秒，完整离开后出现会分配新号；长期遮挡、完全重叠或交叉仍可能需要重选，不能保证身份重识别。
- 轮廓模型失败且运行库可用时尝试内嵌 BlazeFace，降级为检测框；全部不可用时仍能手动框选。
- 当前没有真实年龄估计与 GAN。默认年龄为固定 30 岁演示占位，变龄是演示滤镜；界面和导出均注明演示属性，不能拿来证明模型精度、身份保持或真实年龄变化。
- 本地默认流程不上传照片、不使用 localStorage / IndexedDB 持久化照片；运行库联网兜底会下载资源。未来接入服务后，应按实际网络和服务端保留策略修改说明。清除是应用层释放与像素清空，不保证浏览器底层内存的物理安全擦除。

## 模型接入位置

可在页面启动后、操作前挂载 `window.AgeMirrorAdapters`：

```javascript
window.AgeMirrorAdapters = {
  // 输入：256×256 对齐人脸 canvas；须由实际模型返回年龄。
  estimate: async (image) => ({age: 28, probabilities: [], regression: 28}),
  // 每个目标独立从同一输入生成；返回 canvas、ImageBitmap 或已解码的 Image。
  generate: async ({image, sourceAge, targetAge, requestId}) => resultCanvas
};
```

上段仅说明接口形状，数字不是已接入模型的输出。实际对接必须实现模型调用、输入归一化、输出解码、服务错误和数据策略；当前没有局域网 HTTP 协议实现。单次生成默认 60 秒超时，迟到的返回图像会丢弃；清除/取消后不会写入新会话，但已经提交的外部工作需要服务本身支持取消。
