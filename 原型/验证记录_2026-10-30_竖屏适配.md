# 竖屏显示器适配验证

日期：2026-10-30。回应老师关于纵向全高清显示器的反馈，按1080×1920（宽×高）适配。未增加手势识别，现有自动拍照、占位年龄自动继续、年龄序列自动轮播和镜子模式离开清除继续保留。

大竖屏断点：CSS视口宽至少600、高至少900、宽高比不超过3:4。摄像头整屏显示，结果页用剩余高度展示照片，文字、编号和控件放大；横屏电脑仍使用居中的手机预览，手机窄屏仍按原布局显示。

| 检查 | 本次结果 | 证据范围 |
|---|---|---|
| 大竖屏尺寸 | 1080×1920、720×1280、1440×2560通过 | 镜头铺满、标题及脸部编号放大；结果、选脸、年龄修改、任务、局部/整图对比、默认及九卡总览的关键按钮在视口内，默认页面无纵横溢出 |
| 弹窗与旋转 | 三种尺寸通过 | 选项在屏内；切到1920×1080恢复手机预览，再旋转回来恢复整屏，无须刷新 |
| 原有布局 | 320×568、390×844、430×932、844×390、1440×900通过 | 手机首屏取景、快门可见、横屏桌面居中手机比例、无横向溢出 |
| 上传与导出 | mobile-flow通过 | 真实本地模型检测、年龄扉页、触摸翻页、局部/整图对比、PNG、总览、清除 |
| 返回路径 | navigation-flow七条通过 | 回主页、重拍、逐级返回、撤销未应用年龄修改、已完成任务返回结果 |
| 自动流程 | auto-experience九条通过 | 跟踪编号、多人拍照门限、占位自动继续、轮播、故障与迟到数据隔离，以及真实模型处理双脸模拟视频后自动采集 |
| 大屏手势 | gesture-controls通过 | 本地Hand Landmarker初始化；拍摄前张开手掌约0.7秒触发确认、松手重置、手部轮廓绘制接口和结果页禁用手势通过；未替代真实手部视频和现场误触验收 |
| 视觉检查 | 1080×1920实际截图已查看 | 空闲镜头、真实测试肖像上传后的结果、选项和对比；照片是QA素材，结果仍是演示滤镜 |

新增回归脚本为[portrait-display.cjs](tests/portrait-display.cjs)和[gesture-controls.cjs](tests/gesture-controls.cjs)。本地截图保存在被Git忽略的tmp目录，未将测试肖像作为产品示例分发。多组测试逐项运行后通过；未将并行运行时的浏览器崩溃/超时计作成功。

这些检查使用Windows上的Playwright浏览器视口模拟，不能替代物理竖屏、摄像头位置、观看距离、系统缩放、触摸与帧率的现场验收。演示时先设置系统纵向显示，再最大化浏览器或按F11全屏；首次开启相机仍需用户点击与授权。浏览器缩放会影响CSS视口和断点。
