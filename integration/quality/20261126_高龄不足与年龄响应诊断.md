# 高龄不足与年龄响应诊断（2026-11-26）

莫贝观察到：输入链路修正后，脸部纹路没那么严重，但高龄目标不够老。本次复用保存结果、少量原生读图及运行中的一张GPU诊断，没有训练、换权重、缩放年龄条件或改变线上推理语义。用户本次实拍仍没有落盘，以下不冒充对其具体照片的判定。

## 结论

**现有问题包括年龄变化被跨龄优化压回原照、皮肤细节重建不足和目标年龄监督不直接三个方面，不能归结为只缺训练照片。** 输入裁剪修正减少了不必要的镜像内容，但没有解决这三项模型问题。

### 1. 当前约束组合显著削弱高龄响应

复算 `original-delta-20261124-160055` 全部35张、3路线、5条件的既有原始输出评分，不重新生成。每张源照、源年龄、同龄锚点、原始生成器和年龄条件固定。约束前后比较的是整套180步修正，**还没有分别识别每一个损失项的因果贡献**。

| 全35图 | 原SAM差值，无约束 | 当前原SAM差值＋约束 |
|---|---:|---:|
| 目标60的平均独立外观估龄 | 61.40 | 55.27 |
| 目标75的平均独立外观估龄 | 71.06 | 60.50 |
| 60→75的平均外观变化 | 9.66 | 5.24 |
| 60→75变化不足5年的照片 | 5/35 | 20/35 |
| 目标75但估龄低于60 | 0/35 | 18/35 |
| 跨龄SFace均值 | .69968 | .81295 |

MiVOLO独立于训练损失，只用于外观诊断；不能把这些数值解释为生成脸真实年龄。样本是已看过的开发回归，非新盲测，也不代表亚洲总体。

实际查看64376、65817的原照、无约束60／75、约束60／75：约束后眼睛、嘴形更接近原人，但高龄变化也变弱；65817的75岁仍明显偏中年。无约束输出并非可直接上线的答案，眼／嘴和本人特征漂移显著，纹理也仍不自然。

进一步按**FairFace源参考估龄**描述分组，当前路线在源估龄<40的15张图上，目标75平均估龄51.91；源40–59的14张为62.35；源≥60的6张为77.67。后者目标20仍平均44.78。组间人物／年龄分布不同，不能作单变量因果结论；但它提示生成仍强烈依赖源年龄，既有年轻源脸老化不足，也有年长源脸年轻化不足。

### 2. “目标年龄损失”实际上在模仿旧生成图

代码见 `integration/latent_quality.py`：

```text
direction = E_original(x,target) - E_original(x,source)
initial_target = fitted_anchor + direction
teacher = G(unfitted_source_anchor + direction)
age_loss = KL(FairFace(current_output), FairFace(teacher))
```

`target_age`参与初始编码器方向，但180步优化的年龄目标来自旧teacher的分布，**没有直接要求最终外观达到用户指定的年龄段**，也没有约束同人20／40／60／75的年龄顺序／间隔。teacher使用未拟合锚点，而待修正图使用拟合锚点，两者也并非同一重建起点。

另有身份.8、感知.6、低频颜色.1和位移信赖.05共同约束。身份／感知／颜色都可能阻止一部分真正的衰老变化；不能仅比较系数大小就断言哪项梯度占主导。下一项机制对照应先明确年龄目标，再分离这些损失的影响，而不是直接把所有约束关闭。

`sam_losses.AgeEst.mid`为[1,6,15,25,35,45,55,65,75]，其期望年龄数学上不超过75。最高年龄档内部无法靠该数值头区分80与90；这不是所有≤75老化不足的唯一原因，却是80／90数值监督的结构限制。

### 3. 同龄重建就会损失真实皮肤细节

查看67140的原照、同龄、20、75全脸及未缩放256×256眼周／脸颊：同龄重建已经柔化一些细皱纹、斑点与眼周细节，75岁也没有恢复这些原照细节；目标20仍有明显年长外观。因此“纹路减少”可能同时包含人工刻痕减少和真实细节损失，不能直接等同于自然度改善。

编码器输入256，年龄／身份／感知损失主要在224／256计算，同龄像素参照最高512；缺少直接保证1024高频纹理自然的充分信号。但生成器在无约束方向能表现显著衰老，不能据此断言StyleGAN2完全没有高龄表达能力。应区分潜变量方向、约束、重建、纹理分布四个瓶颈。

### 4. 网页路径也能复现，不是仅离线图库问题

用同一公开署名64376，经过修正后裁剪对应的真实 `/api/prepare` 和 `/api/transform`，新建自己的会话后依次生成同龄25、60、75；只清除此诊断会话。结果为可解码1024 PNG，原始／保色均保留。

| 请求条件 | 模型秒数 | 完整HTTP秒数 | 独立外观估龄 |
|---|---:|---:|---:|
| 原照 | — | — | 24.65 |
| 同龄25，包含首次锚点拟合 | 5.833 | 6.64 | 22.65 |
| 60 | 6.131 | 7.01 | 39.83 |
| 75 | 6.123 | 6.98 | 42.88 |

以实际 `live-64376/report.json`为时间原始记录。代码未修改75为其他条件，保色不改变亮度／年龄方向；实际原生读图同样可见高龄不足，不能说只是评分器错了。该输入与离线FFHQ重采样不同，不能把两协议数值当成精确配对比较。

另直接查看本次75岁原始1024图，仍见额头／脸颊细密刻痕和嘴形变化；细纹数量、眼周／面颊结构与整体年龄感并不协调。因此需要同时判断自然高龄的结构和皮肤，而不能只调皱纹数量或估龄分数。

同一API输入在此前两次和本次诊断中，对齐256与参照1024的RGB逐像素相同，源条件都25，但三次75原始输出的MiVOLO估计41.35／37.11／42.88。逐图W+优化不是位级确定性；目前线上未使用研究评估已有的确定性池化／缩放反向实现。**这需要先控制，否则后续小幅调参收益可能被数值波动混淆。** 当前只证实重复差异，未把所有差异归因于某一个CUDA算子。

### 5. 既有验收线不足以发现绝对年龄不足

现有身份下降≤.02、年龄跨度相对旧基线≥90%的保护线有用，但若旧基线本就变化小，新结果仍可能在目标75时偏年轻。新增逐照片60→75响应、绝对外观年龄误差和盲看目标年龄排序；不得只汇报保护线通过。不把单一估龄分数当质量真值，也不得丢弃65817等失败案例。

代码核对还发现网页“手动修正当前年龄”不会传给 `/api/transform`：前端适配器未接收 `sourceAge`，后端仍使用会话FairFace参考估龄。这不是本次全部高龄不足的已证实原因，但需要在后续界面／接口设计中明确，不能让用户以为修改了GAN源条件。本轮没有悄悄改变源年龄语义。

## 接下来优先做的有界对照

1. 固定输入和数值路径，先在同一输入重复拟合，证明足以比较候选；复用研究已有确定性算子及模型指纹，不改模型权重。不要把不同输入的离线图库和实拍作严格配对。
2. 在相同源锚点和原SAM方向上，仅比较当前teacher与**明确目标年龄段＋同人年龄顺序约束**，先限定可靠监督覆盖的20／40／60／75，80／90单列为未校准条件。使用多视图一致性降低单一估龄头利用假纹理的机会；独立MiVOLO继续只评估，不在这批开发图用它反复调参。
3. 年龄目标明确后，单独比较身份约束的放松／有下限的优化方式，记录各项对年龄方向的梯度投影，寻找年龄响应与身份兼顾的候选。不能单纯降低所有身份保护，或把75暗改90。
4. 最后才扩大匹配推理路线的纹理训练。数据优先高质量同人跨龄参照、可信年龄段、亚洲高龄纹理，而非重复增加成人低清图；AAF／MegaAge可作为清洗后的年龄监督候选，不作为高清皮纹真值。712张合格训练图、70+85、发布方Asian70+仅6张的覆盖缺口仍在。

先用小型开发对照判别机制，再用未调参储备确认；评估同时要求年龄响应、本人特征、原生纹理和检测完整性。当前所有候选继续保留实验状态，本轮没有宣称已得到新的最优模型。
