# 补充年龄数据集来源核查

本轮按官方页面核查AgeDB、CACD、IMDB-WIKI和CelebAMask-HQ，目标是区分年龄监督、身份评估与高分辨率纹理数据。**本轮没有申请访问、联系作者或纳入训练。**来源页摘要和哈希见`evidence/age-dataset-source-check-20261126.json`；页面原文缓存在忽略目录`deployment/age-quality-final/source-search-20261126/`。另对官方未压缩WIKI裁剪归档做限量HTTP范围元数据探测，不提取或使用其中人物图像。

| 数据集 | 来源页披露 | 对本项目的用途与限制 |
|---|---|---|
| AgeDB | iBUG官方页说明仅非商业研究，下载需邮件取得压缩包密码；源图来自互联网，作者不对图像内容负责。 | 可能用于有身份的跨龄评估，但网页没有给年龄档、亚洲高龄占比或原生分辨率统计。不能据论文总规模推定其中有多少高清亚洲高龄脸；获得授权副本后再按人物、日期、原生脸区尺寸与许可审计。 |
| CACD | 作者页称163,446张、2,000人、年龄约16–62，原裁剪包3.5GB，元数据单独817KB；仅学术研究，图像版权属于原作者。作者明确警告年份年龄粗、不建议年龄估计。 | 可评估跨龄身份，但没有70+，不解决高龄纹理；下载、生成式训练和再分发需进一步核对逐图权利。 |
| IMDB-WIKI | ETH官方页称共523,051张，其中IMDb460,723张来自20,284人，另有Wikipedia62,328张；年龄依据出生日期和照片年份推算，作者明确承认错误时间戳、电影静帧等噪声。页面列出IMDB原图10个约24–29GB分片，裁剪包7GB；未披露族裔分布。 | 已用官方MD5核验22.9MB `imdb_meta.tar`。发布年龄65–85、保守单脸过滤后为6,096条，其中发布脸框≥512像素1,077条、≥700像素603条，覆盖1,222个身份ID；其中符合脸框条件者来自511个身份。Wikipedia子集65–85有3,188条单脸候选，脸框最大419像素。只对裁剪归档首32MiB抽取了7张高龄元数据候选：全部已缩到500×500，YuNet实测脸区短边187–253像素，3张原生细节复核发现闪光、阴影、遮挡／妆容等问题。该裁剪包不满足纹理门槛，已停止下载。没有任何图入训；也不能从该来源推断亚洲覆盖。IMDB元数据仍可帮助身份／年龄标签审计，但图像训练需另找合法高清原图。 |
| CelebAMask-HQ | 作者README称30,000张1024×1024图，非商业研究；同一机构单站点内可复制，禁止进一步复制／发布数据。 | 没有照片年龄或族裔分布。或可研究通用人脸局部纹理先验，但不能按高龄或亚洲身份筛选，也不能公开打包训练图；本轮不下载。 |

已有数据才是当前可执行基础：AAF清洗候选约10,983张可用于进一步年龄监督审计，其发布年龄65+的847张原图画布短边246–393，0张达到512脸区纹理门槛；MegaAge-Asian为178×218，发布年龄65–69有训练1,108／测试58，70+为0。最新审核高清训练池712张中，发布标签Asian且70+只有6张。年龄标签可以扩大，亚洲高龄高清纹理覆盖仍须靠逐图许可明确、脸区原生细节合格、身份分组后的新照片补齐。

上述IMDB 1,077条脸框候选来自511个发布身份ID，不能与全部6,096条高龄单脸记录的1,222个身份混用。候选分档为65–69岁451条、70–74岁314条、75–84岁301条、85岁11条。现已冻结本地隔离清单`imdb-hd-quarantine.jsonl`，每条均为`training_admitted=false`；先限量抽查裁剪包原生像素，再决定是否值得继续取图。

不为“数量多”直接整包下载。不能把名称、国籍、外观或模型分类结果当作个人族裔标注。元数据复算使用已有CPU年龄环境中的SciPy，不安装新环境：

```bash
deployment/asia-adaptation/20261123/age-cpu-venv/bin/python \
  integration/quality/audit_imdb_wiki_metadata.py imdb \
  deployment/age-quality-final/source-search-20261126/imdb.mat \
  /新的审计输出.json --candidates /新的本地隔离候选.jsonl
```

`wiki`为另一模式，输入本轮提取的`wiki.mat`。脚本锁定两份元数据SHA256、保留既有输出，不访问网络，也不自行批准入训。官方元数据包MD5校验与WIKI范围成员头校验分别记录，不能混为完整图像归档校验。

Commons在距离上次HTTP429停止27.4小时后做过**一次**原主机访问恢复探测，使用相同公开入口、7个既有候选的批量元数据请求，没有轮换代理。此次TLS握手超时，已停止该来源后续请求；不能说今天又确认了429。记录在`deployment/age-quality-final/commons-access-20261126/access-probe.json`，没有删除原限流标记，没有绕过旧采集器保护，也没有新增Commons照片。
