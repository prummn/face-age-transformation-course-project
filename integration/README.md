# 时空镜真实模型整合版

版本 1.3.0，2026-11-10。用于 2026-11-11 的初步程序原型演示。原型页面接入自有昇腾服务器上的真实模型，完成采集、选脸、参考估龄、多年龄生成、对比、下载与清除。对应概要设计、详细设计 V1.1 中尚未接通的前后端链路。

本次新增同源照片保色与原始模型结果切换、独立 1024 原照参考图、无损上传和直接 1024 回贴；手机首先停在原照，文字移至照片外，便于观察真实颜色。颜色保持是可切换的后处理，未替换模型权重。数据审计与小规模训练对照见 [模型质量目录](quality/)。

## 开始演示

在已配置 `ssh bit-ascend` 的这台 Mac 上，双击仓库根目录 **启动真实模型演示.command**，或运行：

```bash
python3 integration/launch.py
```

启动器会检查本地 65512 端口、启动独立后台、建立 SSH 隧道并等待模型预热，随后打开 http://localhost:65512/ 。页面右上角显示 **真实模型 · 原生 1024** 后即可演示。首启可能需要几分钟，预热后再次连接会复用服务。演示期间保持终端开启，结束时按 Ctrl+C；本机网关和本次隧道随之退出，后台模型保留以便再次启动。

本机只需 Python 3、OpenSSH 和较新 Chrome/Edge，不需要安装 PyTorch。访问服务器仍依赖校园网络/现有 SSH 跳板可用。更换电脑时要单独配置服务器访问，不能只复制 HTML 后声称能运行真实模型。

端口被占用可运行 `python3 integration/launch.py --port 65513`。不要与 `python 原型/serve.py` 同时占用 65512。后者是保留的**离线滤镜原型**；真实入口通过 `?mode=live` 显式启用服务，断线不会回退成滤镜。

## 三分钟演示顺序

1. 展示就绪标记。点击相册上传清晰正面照，或者点击快门启用摄像头。第一次调用摄像头需要浏览器授权。
2. 单脸自动继续；多脸点选一个人物后确认。后台只匹配选中区域，未匹配到清晰人脸时提示重选，不会替换为最大脸。
3. 等待参考估龄和四个目标依次生成。处理页展示真实完成状态和耗时；每个目标均来自同一张原始输入。
4. 手机版首先停在对齐原照，左右切换年龄；大竖屏保留自动翻阅，可暂停。点“对比原照”进入分割线对比，可切换人脸局部和回贴原图；回贴为羽化几何融合，仍可能有接缝。
5. 切换“保留原肤色／原始模型”观察同一结果，无需重新推理；下载名称区分保色图和原始模型 1024。暗光、两侧颜色差异过大或颜色已接近时保持原始结果并显示原因。普通“保存这一页”属于带说明的导出图，总览输出拼图。
6. 从选项进入年龄设置，可修正源年龄、调整 5–90 岁目标。完成后清除本次数据或返回主页，演示下一位。

推荐介绍：“我们已把原来的交互原型和昇腾后台接通。人脸检测、选脸和交互在浏览器完成；后台按选中的人脸对齐，提供参考估龄，再用同一输入生成多个目标年龄。这次展示原生 1024 图像，结果是年龄外观模拟。”

若老师追问，源年龄修正用于年龄差和界面说明；目前 SAM 的直接模型条件是**目标年龄**。FairFace 给出年龄分组概率的期望值，没有独立年龄回归头；不能把参考估龄当作真实年龄。当前主要验证网页端，Android/RK3288 实机与正式准确率、P95、长稳测试仍待完成。

## 接口与几何约定

| 接口 | 用途 |
|---|---|
| `GET /api/health` | 就绪状态、模型版本与原生尺寸 |
| `POST /api/prepare` | 原图 dataURL + 归一化选脸框；返回会话、256 编码输入、独立 1024 原照重采样参考、估龄和源图到 FFHQ 的矩阵 |
| `POST /api/transform` | 会话 + 整数目标年龄；返回 1024 结果、`raw_image` 原始模型输出、颜色处理元数据和耗时；`preserve_color=false` 可关闭校正 |
| `DELETE /api/sessions/{session_id}` | 幂等删除，会话立刻失效；运行中的旧结果不得发布 |

`prepare` 的坐标属于上传原图，后端不重复采用最大脸。`matrix` 和 `inverse` 为 Canvas 顺序 `[a,b,c,d,e,f]`，工作坐标尺寸为 256。前端将逆矩阵线性项按 256/输出尺寸换算，直接绘制完整 1024 图及羽化遮罩，不先缩成 256；不会把旧原型的 browser_affine 逆矩阵用于真实输出。`reference_image` 从上传原图直接采样为 1024，注明“源图重采样”，不声称其拥有原照缺失的细节。

`source_color.py` 估计本张原照与输出双颊 Lab 色度差，使用有上限的局部 a/b 偏移；不设置统一肤色、不用人群分类器。内部保留 Lab L，但 RGB 色域裁剪及量化会造成微小明度差异。暗光、两颊色差过大、过曝或样本不足时跳过。固定几何区域不能保证分离所有皮肤、眼镜、胡须和侧脸，局部色差仍可能存在；原始输出始终可查看、下载。它不是重新训练、真实肤色恢复或身份准确率提升的证明。

本版为演示所需的简化同步接口，逐目标状态由前端管理，尚未完整实现 V1.1 规划的 `/v1/jobs` 异步队列、请求幂等与鉴权机制。推理串行、排队限额 8，单目标失败可重试；取消会停止前端等待和后续目标，已开始的单次 NPU 运算可能完成后被丢弃。后端具备可选 2048 超分调用，整合页面当前固定原生 1024，不宣称完整验收了 2048 前端交互。

## 照片与错误处理

确认选脸前会说明照片发送到自有服务器。新服务不将照片、生成图或请求内容写入文件，不建立人脸库，不加入训练集；只保留本次对齐脸的内存会话。清除和返回主页请求删除会话，闲置 30 分钟自动过期，每 30 秒清理一次；断线时由到期机制释放。浏览器已下载的文件不会被删除。应用层释放不等于物理内存擦除。

相册支持 JPG/PNG/WEBP，前端限制 15 MB、短边至少 256，最长边缩小至 1800；后端另验证编码、像素数和请求大小。服务失联会显示未就绪或失败并保留可重试入口，不能把滤镜结果冒充真实模型。

## 故障恢复

- **无法 SSH**：先在终端运行 `ssh bit-ascend hostname`；检查校园网络与 Mac mini 跳板。服务器作业重建可能需要原有隧道恢复流程。
- **NPU 0 被占用**：启动器明确报错；先核对占用任务，不要直接结束其他训练进程。
- **长时间未就绪**：检查 `ssh bit-ascend 'tail -80 /data/home/1120231322/scow/face-age-integration-20261110/logs/backend.log'`，修复环境后重启该服务。
- **页面未连接**：确认启动的是整合入口，选项中点击重新连接。若 SSH 已断开，退出启动终端后重新执行启动命令。
- **某张脸失败**：换用清晰、正面、无遮挡照片，重新框选所需人物；后台不会越过选择去处理其他人。
- **相机没有权限**：允许 localhost 的摄像头权限，或用相册演示。手机 HTTP 局域网地址不能直接调用摄像头，需可信 HTTPS，当前启动器只开放本机。

重新部署后端的代码命令（不会同步权重或照片）：

```bash
ssh bit-ascend 'mkdir -p /data/home/1120231322/scow/face-age-integration-20261110'
scp integration/backend.py integration/source_color.py integration/start_backend.sh integration/backend_requirements.txt bit-ascend:/data/home/1120231322/scow/face-age-integration-20261110/
```

已有后台运行时，更新代码需要由维护者停止该目录记录的服务进程再启动，不应使用无范围的 `pkill python`。
