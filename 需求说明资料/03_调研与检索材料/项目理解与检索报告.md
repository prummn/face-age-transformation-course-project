### 4.1 年龄分类与回归的关键区别

DEX 可表示为：模型预测每个年龄的概率 `p(k | x)`，输出连续预测 `a_hat = Σ k × p(k | x)`。它结合了分类输出与数值期望，但不因此自动成为“另有一个用回归损失训练的回归分支”。

Mean-Variance 方法联合分类损失、均值误差和方差约束，更适合作为本题 C 的重点候选。如果老师要求独立的分类与回归模块，可再考虑共享特征网络加“年龄段分类头 + 连续年龄回归头”，这属于另一个待设计方案，不能说 DEX 原论文就是双分支模型。

输入照片体现的是外观，无法从图像保证恢复精确的真实年龄。评测必须写明使用真实年龄还是表观年龄标签，训练和测试也不能混用两者。分类分布的最大概率不能未经校准直接当作可信的置信度。

### 4.2 生成方法如何选择

| 比较项 | SAM | LATS |
| --- | --- | --- |
| 公开入口 | [作者仓库](https://github.com/yuval-alaluf/SAM) | [作者仓库](https://github.com/royorel/Lifespan_Age_Transformation_Synthesis) |
| 对课堂需求的适配 | 官方推理示例支持一次指定多个数值目标年龄、前后或并排输出 | 官方代码提供多个年龄锚点的整段变化与插值流程 |
| 值得关注的效果 | 细粒度年龄控制、身份保持 | 全生命周期、头部形状与纹理共同变化 |
| 工程限制 | README 面向 Linux/macOS 与 NVIDIA CUDA，CPU 并非原生支持；需验证环境和权重获取 | README 有 Linux/Windows 脚本及输入照片要求；原训练配置不能直接视为本组硬件需求 |
| 需避免的误解 | 指定目标岁数并不保证结果外观误差为零 | 插值或年龄锚点不等于逐岁精度已经验证 |

建议先以 SAM 验证“同一张图、多目标年龄”的推理可行性，以 LATS 作对照；若讨论后更重视儿童成长或全头部形变，再调整优先级。这是检索后的建议，尚不是正式选型。

还要核对 D 中“根据现有年龄”的实现要求。候选模型可能主要接收图像和目标年龄，并不会显式使用系统 C 输出的当前年龄。产品层使用当前年龄计算年龄差、组织展示，不能被说成网络已显式接收源年龄；如果老师要求将源年龄和目标年龄都作为生成网络条件，就要检查或修改模型接口，并安排相应训练验证。

## 5 问题陈述与产品范围草案

### 5.1 可供课堂采用的问题陈述

面向希望直观体验自身不同年龄外观的普通用户，以及需要展示和评估人脸年龄变换技术的课程演示人员，本项目拟构建一套基于对抗生成网络的人脸年龄变换系统。公开同类产品提供了变老、变年轻、年龄阶段选择及结果分享等功能，但课程项目还需要将图像采集、人脸处理、年龄估计、多目标年龄生成和图像合成组织为可部署、可测试的完整流程。

系统应支持用户通过摄像头获取照片，自动检测并截取人脸，采用多分类与回归相结合的方法估计当前年龄，并根据人脸图像、当前年龄信息和用户选择的目标年龄生成多个年龄版本。系统应尽量保持人物身份特征，提供原图与生成图的对比、图像合成和结果导出，并对未检测到人脸、存在多张人脸、输入质量不足或处理失败等情况给出明确反馈。系统输出用于年龄外观模拟和技术展示，其效果通过年龄控制、身份保持、图像质量和处理耗时等指标评价。

这段陈述是根据课程与检索资料形成的提案，没有声称已做用户访谈、验证市场空缺或测得竞品缺陷。

### 5.2 用户与首版范围建议需要查看完整流程、测试结果与技术依据；开发维护人员需要更换模型、查看任务错误和复现实验。首版不必因此引入独立管理员账号或登录系统。

建议首版完成单人照片流程：摄像头拍照及补充上传、人脸选择、年龄估计、多个目标年龄生成、对比合成、导出和清除本次数据。多人照片可先要求选定一张脸；生成采用拍照后的异步任务。连续视频变龄、多人同时变龄、社交社区和复杂美颜留作扩展候选。

若首次验证只覆盖成人，可先以成人样例展示，但不能据此擅自删掉教师可能要求的儿童年龄目标。模型支持范围与课程验收范围需在讨论后一起写清。

## 6 从来源到可验收需求

下列需求编号可延续到需求规格、概要设计和测试用例中。优先级 P0 表示建议首版核心，P1 表示补充或取决于课堂口径。

| 编号 | 优先级 | 需求及主要输入输出 | 验收要点 | 依据 |
| --- | --- | --- | --- | --- |
| FR01 | P0 | 打开摄像头预览、拍照、重拍；输出原图 | 设备可用时取得照片；拒绝权限或无设备时给出可操作提示 | A；A05、A06 |
| FR02 | P1 | 上传 JPG/PNG 等约定格式，校正方向并校验尺寸 | 合法图片进入相同处理流程；损坏、超限或不支持格式被明确拒绝 | A03、A05 |
| FR03 | P0 | 检测和选定人脸，裁剪对齐；输出人脸图、框和变换信息 | 无人脸停止并提示；多人脸选定一张；不得静默选错人 | B；P08、P09 |
| FR04 | P0 | 用分类与回归相结合的方法估计年龄 | 输出预测年龄和约定的分类信息；算法结构与报告一致，测试集有明确标签定义 | C；P01、P02 |
| FR05 | P0 | 选择多个目标年龄，明确绝对年龄或年龄差 | 至少 3 个目标形成有序列表，非法或不支持的年龄被提示；3 个是本报告建议，非教师给定数量 | D；A02、A03、A06 |
| FR06 | P0 | 使用 GAN 路线对原始人脸生成多个目标版本 | 每张结果对应同一来源与正确目标；部分失败单独显示，不混用其他任务的旧图 | D；P03–P07 |
| FR07 | P0 | 处理图像合成，展示原图、单目标和多年龄拼图 | 年龄标签与图像匹配；尺寸与颜色一致；回贴原图是否必做待确认 | E；A01、A02 |
| FR08 | P0 | 导出单图及拼图；保留约定的目标信息 | 导出文件可重新打开，内容与当前任务一致；保存失败有提示 | E；A01–A06 |
| FR09 | P0 | 展示任务阶段、错误和重试入口 | 页面能区分等待、处理中、成功、部分失败、失败；重试不产生结果混淆 | 工程落地建议 |
| FR10 | P0 | 在采集前说明照片处理方式；清除本次照片和结果 | 用户可清除应用管理的临时数据；长期保存由明确操作触发 | 照片处理场景与工程建议 |

FR07 应拆成两个测试对象：拼图排版用于展示；原图回贴用于把生成人脸融合进原照片。若老师要求后者，必须保留 FR03 的空间变换信息，并确定融合范围是面部还是全头部。头形、头发变化较大时，不能只把小块面部贴回去就认为完整实现了生成效果。

建议用户流程为：

```mermaid
flowchart LR
    A[摄像头拍照或上传] --> B[检测并选定人脸]
    B --> C[裁剪对齐与年龄估计]
    C --> D[选择多个目标年龄]
    D --> E[GAN 生成年龄版本]
    E --> F[合成与对比]
    F --> G[导出或清除]
```

失败提示与重试应覆盖每个处理阶段。年龄估计结果可展示给用户，但是否允许用户提供或修正源年龄，需要与“现有年龄”的课程口径一起确认。

## 7 性能指标草案与验证办法

以下数值均为**候选目标，尚未实测，也不是课程原文给出的指标**。正式承诺应在确定演示设备、模型、输入尺寸与运行方式后修订。必须同时记录 CPU/GPU、显存、操作系统、模型与权重版本、输入输出分辨率、样本数量、冷启动或预热状态。

| 指标 | 建议的首轮目标或观察项 | 测量方式 |
| --- | --- | --- |
| 摄像头交互 | 720p 预览达到 20 FPS；拍照操作反馈不超过 1 秒 | 指定摄像头与电脑，统计持续 60 秒的有效帧率和操作反馈；不含后续生成耗时 |
| 人脸定位 | 在预先约定的清晰正面单人样本上，有效检测率至少 95% | 至少 100 张带人脸框标注的有效图，匹配标准如 IoU ≥ 0.5；负样本另统计误检，不能剔除检测失败样本 |
| 年龄估计 | 候选目标 MAE ≤ 5 岁，同时报告误差在 5 岁内的比例 | 独立测试集，先明确真实或表观年龄；按年龄段统计，按人物划分训练与测试，避免同人泄漏 |
| 单目标生成耗时 | 指定 GPU 上预热后 P95 ≤ 10 秒，作为初测目标 | 固定尺寸，至少 30 次；从模型收到已对齐人脸到生成图返回。另记预处理、排队、后处理和冷启动 |
| 多目标端到端耗时 | 4 个目标从提交到可查看全部结果的 P95 ≤ 45 秒，作为初测目标 | 包含检测、估龄、生成、合成与任务调度；失败率和超时一起报告，不能仅统计成功的最快样本 |
| 目标年龄控制 | 记录生成脸估计年龄与目标年龄的误差、年龄段命中及变化趋势；阈值在基线后确定 | 使用与训练监督尽量独立的估龄模型，并补充盲评；不能让同一估龄模型单独给自己的生成约束打分 |
| 身份保持 | 记录人脸特征相似度分布和“是否像同一人”的盲评；阈值经基线校准 | 固定识别模型，以真实同人和异人样本校准；不直接套用任意 0.8 等阈值 |
| 视觉和合成质量 | 记录面部畸变、接缝、边缘残留、背景误改的比例 | 至少 30 张、多年龄目标的固定样本集，统一标注规则；小样本人工验收不包装成 FID 结论 |
| 异常处理 | 约定异常用例均有明确反馈且应用不中断 | 拒绝权限、无设备、无人脸、多人脸未选择、损坏文件、尺寸超限、模型超时、保存失败 |
| 数据清除 | 清除后应用管理的临时原图和生成图不可再从任务入口访问 | 检查临时目录、任务记录和缓存引用；用户已自行导出的副本另行说明 |

采集、检测、估龄、生成和合成应分别记录耗时，再记录端到端耗时。界面能流畅预览摄像头，不等于 GAN 可以实时生成。若初测不满足候选目标，应调整模型、分辨率或目标数量，再由组长统一性能承诺。

## 8 后续技术调研的起点

这部分提供“每人比较两个方案”的起点，不是已经批准的实现设计。

| 环节 | 方案一 | 方案二 | 比较重点与初步建议 |
| --- | --- | --- | --- |
| A 采集 | 浏览器 getUserMedia | 本地 OpenCV VideoCapture | 浏览器方便交互，本地链路便于算法验证；先确认做网页还是桌面，再统一图片接口。浏览器权限及安全上下文规则见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia) |
| B 人脸 | MTCNN | RetinaFace | 比较正面与侧面样本的定位、关键点、耗时、依赖和模型授权；不凭论文排名直接判断本机速度 |
| C 年龄 | DEX 分类概率取期望 | Mean-Variance 联合分类与分布约束 | 先确认老师口径，再统一标签、数据和测试集；[年龄估计参考仓库](https://github.com/yu4u/age-gender-estimation)可作代码阅读起点，其旧环境与权重条件需要核对 |
| D 生成 | SAM | LATS | 比较目标控制、本人相似度、输入限制、分辨率、显存和部署难度；先验证预训练推理，再决定微调 |
| E 合成 | 逆变换后用软掩膜羽化融合 | 逆变换后用泊松融合，如 seamlessClone | 前者便于控制，后者可改善部分边界颜色过渡；二者都可能在头形变化或背景复杂时失败，需用实际图片比较 |

原图合成的必要步骤通常包括：保留裁剪和对齐变换、估计需要替换的区域、将生成结果映射回原图、处理颜色和边界，再导出。需要头发或全头部替换时，可另调查分割或抠图；本次浏览了 [MODNet 作者仓库](https://github.com/ZHKKKe/MODNet)，但没有完成该模块选型。

本次没有确定前后端框架、数据库产品或模型服务部署方式。若只保留当前会话，可用临时任务数据；若需要历史记录，则至少管理任务、源图引用、预测年龄、目标列表、各目标结果状态和模型版本。即使最后采用轻量存储，也需在课程要求的数据库或数据设计章节说明结构与理由。

预训练代码、模型权重和数据集的使用条件应分别核对。年龄估计参考仓库明确提示部分数据和权重限学术用途，不能仅看到代码开源就假设所有资源均可商用；这会影响将来的分发方式。

## 10 课堂需要形成的结论

1. 确认问题陈述、主要用户和核心流程，明确至少 5 项功能。
2. 确认“多分类与回归结合”的最低实现要求。
3. 确认允许预训练模型集成，还是必须训练或微调，以及“当前年龄”是否必须作为生成网络的显式条件。
4. 确认目标是精确年龄还是年龄段、儿童目标是否必做、需要多少个目标。
5. 确认图像合成是拼图展示还是包含原图回贴，是否要求连续视频。
6. 明确组员、可用 GPU/显存、演示平台、阶段截止日期和各人的两个候选方案。

这些属于课堂讨论尚待确定的项目决策；不影响今天先提交本次检索与问题陈述草案。
